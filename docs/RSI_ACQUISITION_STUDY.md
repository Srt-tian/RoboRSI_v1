# RSI：等预算补数据的一轮检验

2026-09-23。已完成离线反例选择、物理采集、模型更新和新场景验证；**未证实反例采样优于随机补数据**。
这是常规主动学习思路的可复现检验，不把近邻回归、有限候选接口或一次自动更新宣称为新算法。

## 实际 pipeline

1. 复用上一轮 600 个训练场景，按任务/阶段做三折交叉拟合，三个模型种子，共 9 个网络；旧测试标签不进入采样或训练。
2. IDC 的 8 个 CPU worker 生成 1,200 个无候选结果标签的检查点，仅返回可见输入。候选池按任务及短/长延迟均分。
3. 随机、模型分歧、历史反例三种方法各选 180 个场景，预算均为 540 条候选分支。反例评分使用同任务 15 个近邻的交叉拟合遗憾；两种定向策略均保留 20% 随机探索。
4. 三组请求合并为 393 个不同场景，在 IDC 执行 1,179 条物理分支。共享执行不减少各策略账面的采样预算。
5. CLOUD 从相同初始模型分别更新，包含“只重训旧数据”控制组；每组 3 个种子、400 次更新、每批 256 个场景，共 12 个更新模型。新的 180 个验证场景选 checkpoint，包括第 0 步。
6. 冻结模型/采样/验证集哈希后，构建 300 个新 IID 和 300 个新长延迟测试场景，三个固定模型种子先在场景内平均，再计算配对区间。

更新数据已经包含长延迟，新长延迟测试是目标域的新场景留出，不是更新模型从未见过的延迟分布。没有增加任务类型或真实相机输入。
模型仍为 `32→64→64→2` 的 6,402 参数 MLP；29 个结构化上下文特征和三维候选 one-hot，输出成功概率估计与剩余用时估计。

## 结果

| 方法 | 新 IID 成本 | 新长延迟成本 |
| --- | ---: | ---: |
| 冻结原模型 | 0.31673 | 0.42037 |
| 只重训旧数据 | 0.31772 | 0.41974 |
| 随机补数据 | 0.31499 | 0.40678 |
| 模型分歧补数据 | 0.32076 | 0.40840 |
| 反例补数据 | 0.31005 | 0.40247 |
| 固定异步刷新 | 0.30952 | 0.43032 |
| 任务阶段查表 | 0.30407 | 0.42655 |

主要对照为两组等权合并后的反例减随机成本差：**−0.00462，95% CI [−0.01409, +0.00439]**。
相对模型分歧为 −0.00832，探索性 CI [−0.01839, +0.00144]，也跨零。
相对冻结模型/只重训旧数据的小幅改善，不能代替等新增数据预算的比较；新 IID 上任务阶段查表仍更强。
区间由 4,000 次场景 bootstrap 得到；600 个场景不因模型种子而扩大分母。只有一个采样随机实现，未估计采样种子总体的不确定性。

## 资源和证据

- IDC 可见 16 个 CPU 线程、约 60 GiB 内存和 9,728 MiB GPU 分区；本轮采样和便携推理使用 CPU。
- 8 worker 的候选前缀、验证、补数据、两个测试集采集分别约 7.1、15.1、29.5、20.2、22.8 秒。CUDA 模型更新在另一开发机完成，没有提交 EIP 集群任务。
- 含跨机器预检的全部 **3,555 条分支**通过状态、时间、动作、成功和成本审计；完整逐步记录留在 IDC，Git 和本机 Web 保留明确标注的缓存与全量哈希索引。
- 固定导出 `counterexample_11` 的 CPU 选择与原记录 **600/600 一致**。2,000 次 CPU 计时中位数 **0.054 ms**、P99 **0.065 ms**，不含视觉/通信/IK/伺服。
- GPU 环境为 PyTorch 2.7.1+cu128，矩阵精度 `high`、TF32 开启。CPU 与 GPU 默认分数并非逐位相等；另外核对严格 FP32 实现，最大分数差约 1.1e−6。仅检查上述固定模型，不扩展为所有模型的保证。
- 30 段新增录像直接播放归档 qpos/qvel，不冒充重新执行。Fetch Pick 的派生位姿缓存比积分状态早一个 2 ms 物理步；核对观测时作时刻对齐，显示的 qpos 保持归档原值，核验误差为零。
- 一个跨机器重跑案例的最大速度差约 1.3e−13，成功、用时、成本相同。失败的逐位对齐尝试和诊断记录保留，不承诺跨机器逐位一致。

缓存/积分时序依据 [MuJoCo 3.6.0 仿真说明](https://mujoco.readthedocs.io/en/3.6.0/programming/simulation.html)，并核对安装版本中 Fetch 的 `_step_callback`。推物回调会刷新派生量，抓取回调不执行这一步。没有改动本轮冻结的环境行为或标签。

## 下一步机制假设

优先研究“当前观测相同，已提交的动作队列不同”时，感知刷新、等待和消费旧信息是否应作相反选择。
用配对检查点只干预待执行队列，比较队列条件化规则、相同容量判断器及延迟阈值，而不是仅增加普通 MLP 参数。
执行时刻条件化已有相关工作，创新性仍须与主动感知、RTC 类方法逐项核对。之后再加入独立采样种子、第三类接触任务、图像输入和全任务多次判断。

## 只用 CPU 复测判断开销

已导出的权重只需要 NumPy。下面的命令不需要 PyTorch、MuJoCo 或 GPU，也不连接机器人。

```bash
python scripts/physics_rsi_cpu.py --mode benchmark \
  --model experiments/mujoco/2026-09-23/rsi_acquisition_001/judge_cpu.npz \
  --rows experiments/mujoco/2026-09-23/rsi_acquisition_001/test.json \
  --output /tmp/roborsi_cpu_new_check.json
python scripts/verify_research_evidence.py
```

复刻 GPU 训练时还需记录矩阵精度设置；本轮为 `high` / TF32。不同硬件的训练权重或仿真状态不保证逐位一致。
