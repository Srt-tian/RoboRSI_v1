# 决策逻辑仿真与论文实验档案

**本机入口：**在仓库根目录运行 `python -m http.server 8790 --bind 127.0.0.1`，打开 **http://127.0.0.1:8790/paper/**。页面、视频、数据均来自当前控制机，不依赖推理机或外部 CDN。

## 仿真回答什么问题

这个环境检查：当完整粗计划遇到位移、缺观测或滑落时，是否正确选择等待/修订/恢复；异步建议返回后，版本检查是否能阻止过时建议被采用。环境独立于机器人运行时，复用 `rsi.contracts.checkpoint` 与 `matches_current`，没有 CAN、机器人 SDK 或模型服务调用。

**它是运动学与抓取阈值代理，不是 MuJoCo，也不是 Piper 数字孪生。** 夹爪在 Cartesian 空间沿插值路径移动，以椭圆捕获区域判定夹住，再以附着/脱落规则更新物体位置。未建模关节可达性、接触力、摩擦、形变或整臂碰撞；因此只能验证决策与时序逻辑，不能预测真实抓取成功率。

没有下载模型或资产，也没有为了演示假装调用 Jev。提案器直接基于带噪观测提出有界 XY 修订，所有反应式方法共享这个规则。固定计划、即时规则和注入延迟的策略均有相同的跟踪故障保护。

## 四种策略与六种场景

| 策略 | 机制 | 对照意义 |
| --- | --- | --- |
| `fixed_plan` | 仅初始观测，执行完整计划；保留硬故障保护 | 当前视觉开环思想的简化基线，不等同于真实 GPT 成绩 |
| `instant_rules` | 在阶段检查点立即用同一规则生成修订 | 强规则基线，避免只与弱开环对比 |
| `delayed_unchecked` | 同一规则提案延迟返回，未复查就提交下降段 | 有意去掉版本复查的消融；仅存在于本仿真 |
| `delayed_checked` | 返回后检查契约/阶段/语义 revision，过时则重新观察 | 验证 `matches_current` 的时序作用 |

场景包括正常、一次移位、等待期间再次移位、遮挡期间移位、抬升后滑落和跟踪故障。正常任务不调用修订；观测缺失时等待；超预算或硬故障终止。世界移位使用共同绝对时间表，感知噪声按 seed 和世界时间生成，不受各方法的调用次数影响。

语义 revision 由仿真中的特权事件检测器提供，夹持状态也是简化反馈。**真实感知能否可靠检测变化，尚未验证。** 滑落是按抬升阶段注入的压力测试，不是假设现实世界可以完全回滚。

## 已完成运行：run_001

[完整归档](../experiments/simulation/2026-09-22/run_001/) · [CSV](../experiments/simulation/2026-09-22/run_001/summary.csv) · [结果矢量表](../experiments/simulation/2026-09-22/run_001/summary.svg) · [MP4 对照视频](../experiments/simulation/2026-09-22/run_001/videos/shift_during_wait.mp4)

24 个种子 × 6 个场景 × 4 个方法 = **576 个 episode**；记录 **269,616 个 200 Hz 虚拟状态**。延迟策略使用 0.35 s 注入延迟，阶段检查按 20 Hz 执行；导出 6 个场景的四方法视频，20 fps、1280×850，回放 seed 0。全部种子可在[全量过程页](../paper/process.html)交互浏览并下载单个 episode CSV。

| 方法 | 入筐 / 全部 episode | 平均虚拟时长，含失败 | 过时采纳 | 过时丢弃 |
| --- | ---: | ---: | ---: | ---: |
| 固定计划 | 24 / 144 | 1.875 s | 0 | 0 |
| 即时规则 | 120 / 144 | 2.317 s | 0 | 0 |
| 延迟、不复查 | 120 / 144 | 2.633 s | 24 | 0 |
| 延迟、版本复查 | 120 / 144 | 2.517 s | 0 | 24 |

各方法分母都包含 24 个注入硬故障的保护停止，未静默剔除。固定计划因失败较早结束，其平均时间不能解释为更高效率。

**有用的观察：**等待期间二次移位时，不复查策略最终也能被后续重抓救回，但浪费了一次过时动作：平均 3.95 s。版本复查先丢弃旧建议，平均 3.15 s，减少 0.80 s，即约 20.3%。即时规则为 2.65 s，仍然最快。正常场景四种方法完全相同；简单移位场景的额外复查还增加了一点等待。

**结论限于这个代理模型：**版本复查避免了过时采纳，在指定延迟扰动下减少恢复成本；没有提高这组反应式策略的最终成功数。它不证明小模型比规则好，也不证明已实现 RSI 学习。种子只改变小范围位置和噪声，各种子结果高度相似，不能包装成大量独立真机证据。

## 每轮保存哪些过程量

| 文件 / 页面 | 内容 |
| --- | --- |
| `benchmark.json` | 配置、方法、源代码指纹、每个 episode 的结果/事件、seed 0 的 20 Hz 可视轨迹 |
| `process.jsonl.gz` | 全部 episode 的 200 Hz 状态；每行一个 episode，包含 `columns / phases / samples` |
| `summary.csv`、`summary.svg` | 可复用结果表；SVG 中的文本和数据可编辑 |
| `videos/*.mp4` | 同一世界时刻的四方法画面；各方法结束后冻结，不用视频加速掩盖等待 |
| `index.html` | 该轮视频、统计、事件和可视回放 |
| `manifest.json` | 文件大小与 SHA256、源码内容指纹、导出器和 ffmpeg 版本 |
| `paper/process.html` | 解压全量过程，选择任意 seed / 场景 / 方法、5 ms 单步、播放、下载 CSV |
| `paper/index.html` | 多轮论文档案入口，另外连接历史真机证据与合成判断工作台 |

逐步字段包括时间、夹爪 XYZ、物体 XYZ、当前 XY 目标、开闭/附着、语义 revision、阶段编号、待返回建议 revision 和可见性。这里夹爪坐标是运动学模拟状态，未模拟跟踪动力学。`checkpoint` 事件记录观察量与路由；请求、移位、过时丢弃、修订提交、滑落、恢复与结束另有带时间事件。

本版没有真实模型输入输出 token 或实测 API 延迟可记录，因此模型调用始终为 0；不能把 `analytic_requests` 当模型调用。后续接入模型应新增模型版本、请求/回复、费用、真实墙钟与动作效果记录，并继续保留此规则基线。

## 运行与归档新实验

```bash
# 核心仿真只使用项目环境；额外视频导出需要 Pillow 与本地 ffmpeg。
python -m pip install -e '.[media]'

roborsi-sim --seeds 24 --start-seed 24 --decision-delay 0.35 \
  --output experiments/simulation/2026-09-22/run_002
python scripts/export_simulation_media.py experiments/simulation/2026-09-22/run_002
python scripts/verify_paper_run.py experiments/simulation/2026-09-22/run_002
python scripts/build_paper_index.py
python -m http.server 8790 --bind 127.0.0.1
```

没有安装 console entrypoint 时可用 `PYTHONPATH=src python -m roborsi.simulation ...`。每次使用新目录；仿真入口拒绝覆盖，媒体导出拒绝修改已有 manifest 的封存运行。失败的半成品目录不要冒充封存结果，修复后新建运行目录。

`verify_paper_run.py` 检查归档文件指纹、episode 是否完整、过程样本数量、列数及 5 ms 时间间隔。内容指纹不提供签名认证。生成实验时的源码由内容哈希标识，manifest 保留当时 Git 基线；不能把基线 SHA 当成这些新增未提交代码的执行版本。

## 下一步如何提高证据质量

先增加延迟扫描、检测漏报/误报、候选缺失和观测偏差，再接真实 URDF 的 IK/碰撞检查与物理接触引擎。最后在固定候选库与相同复位协议下比较规则、Jev/本地模型与 GPT 重规划。RSI 的收益要通过冻结记忆/模型后的留出实验验证，不能从本页的规则仿真推断。
