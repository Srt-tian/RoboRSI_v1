# 面向真机的有限候选判断与 RSI

2026-09-28，本轮完成了观测接口、Piper 候选编译和 RoboTwin 小规模物理预检。
没有新训练视觉模型，没有新的真机运动；这里的 JEV 指非生成式有限候选判断，不是 JEPA 或官方 Jev 模型复现。

## 当前可运行的部分

| 模块 | 实现与输出 | 当前边界 |
| --- | --- | --- |
| 实测输入 | `observations.py`、`robotwin_feedback.py`：按关节名提取 qpos/qvel，明确单位；Piper 标准化 q14 离线适配 | 夹指坐标不等于开口宽度；命令另存，物体真值不进入测量输入 |
| 时效检查 | 区分采集与可用时间，检查时钟、年龄和传感器偏斜 | 已测试接口；仿真渲染时物理暂停，不是假装真实异步相机 |
| 有限候选 | `piper_candidates.py`：保持另一臂和夹爪，生成基坐标系小幅相对运动 | 六自由度 Piper 专用几何适配；返回无执行授权的离线产物 |
| 轨迹执行接口 | 复用有界 IK、中心线几何检查、重定时与 200 Hz 平滑采样 | 新候选只做离线逐点检查；真实 200 Hz 发送证据仍来自历史实验 |
| 物理数据 | `robotwin_probe.py`：RGB、实测反馈、指令、结果、退出码；显式释放 SAPIEN/CUDA 资源 | 原生提案使用特权状态；自定义抓取子任务不计为完整基准任务 |
| 分支配对 | 冻结初始规划的 position 和 velocity，再核对完整前缀摘要与分叉物体姿态 | 已验证一个父条件的三个分支；不宣称完整物理引擎快照 |
| 判断与 RSI | 预留有限候选判断、补观测及请求新候选的方向；数据保留失败和不可执行原因 | 新视觉选择器、自动更新和真机自主恢复尚未验证 |

## 已完成的检查

- 原生双臂抬锅、交接各一次，任务完成且子进程均退出 0。交接新旧 3,778 步控制和实测数据完全一致；
  抬锅相差 5 步。两个案例不能替代大规模环境稳定性评测。
- 24 个固定历史 Piper 反馈帧 × 5 个小幅候选：105 个通过全部 200 Hz 样本检查，
  5 个因有界 IK 被拒绝，10 个因起始 TCP 超出本轮工作空间被拒绝。筛选参数未因结果而放宽。
  历史 FK 一致性是代码/记录检查，不是实际标定误差测量；120 个候选不是 120 次抓取试验。
- 首轮 3 个偏差条件 × 3 个固定候选：无偏差时 3 条分支成功，±40 mm 偏差时 6 条分支失败。
  独立规划的前缀也不完全相同，所以这批结果不作同状态因果统计。
- 固定负偏差组第一条“继续”分支的规划前缀，追加 3 条验证：均重放 1,003 步，
  控制/实测摘要与来源一致，分叉物体姿态差为 0；三条分支仍失败。没有按成功挑选前缀。

**当前证据支持先改候选与观测时机，不能支持训练一个更大判断器就能解决问题。**
固定横移重夹在当前偏差条件下没有救回案例；给失败候选重新排序没有额外成功空间。

通过候选的完整离线编译耗时中位数约 239 ms、最大约 507 ms（本次开发机测量），包含逐点几何检查。
这段计算不能放进 5 ms 的发送线程。下一步需要提前编译或异步准备候选，并在使用时检查状态版本和时效；
本轮尚未实现这条在线调度链路。

## 下一轮具体研究问题

把两类问题分开验证：

1. **候选已有可行解，但排序不确定**：判断补看或小幅诊断能否改变排序，并计入真实时间成本。
2. **当前候选普遍无效**：请求更新局部目标或新候选，而不是持续给同一菜单重新打分。

RSI 随之区分“选错了已有好动作”和“根本没有给出好动作”：前者收集判断器对照，后者收集提案/技能修订。
本轮还只是通过物理分支暴露了第二类失败，没有训练一个能可靠自动归因的模型。

拟比较同信息、同候选、同交互预算的直接 Q、固定重夹、总是补观测，以及更新判断器、更新提案器、分流更新和随机采集。
先把检查点前移到失误闭合尚未将物体推离可恢复范围之前，再检验观测是否有用。
如果简单视觉定位加固定规则已经覆盖案例，就不包装成复杂决策模型的收益。

候选评分、失败恢复、主动感知和模块分工本身均不作为原创声明。需要对照
[Q-Planning](https://q-planning.github.io/)、[RoboRecover](https://arxiv.org/abs/2609.28952)
与 [FAR](https://arxiv.org/abs/2607.01111)，再用冻结独立测试检验上述归因和采集机制是否有独立贡献。

## 离线使用

```bash
PYTHONPATH=src python -m unittest discover -s tests -p test_observations.py -v
python scripts/piper_candidate_audit.py \
  --urdf /path/to/commissioned_dual_piper.urdf \
  --feedback experiments/2026-09-17/servo20_three_deep.jsonl.feedback.jsonl \
  --output runs/piper_candidate_audit \
  --frames 24 --tcp-floor-m 0.006
```

`0.006 m` 是本轮历史预检参数，不可直接当作当前现场桌面标定。候选始终保留
`execution_authorized=false` 和 `requires_fresh_scene_and_seed=true`；这里没有连接 SDK 或写入 CAN。

RoboTwin 需要单独准备其官方依赖、资产和已固定的源码版本，主仓库的基础依赖不会自动安装模拟器。
具体协议和实验顺序见 [ExecPlan](plans/2026-09-28-deployable-recovery.md)。

本机 Web：`http://127.0.0.1:8790/paper/#deployable`。同页展示实际回放、指令/夹指测量曲线、
逐候选拒绝原因和开发结果。精选缓存约 7 MB；完整物理记录和规划数组保留在执行机。
