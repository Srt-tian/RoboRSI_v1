## 本轮落实到代码的部分

| 问题 | 本轮实现 | 限制 |
| --- | --- | --- |
| 失败依赖会话回忆 | `rsi/evidence.py`：导入指标、规则分型、保留记录与指纹 | 不自动分析图像或完成因果归因 |
| 候选只有文字描述 | `rsi/evaluation.py`：限制关节编辑，复用编译器比较基线/候选 | 初始状态、场景、阶段结构、夹爪事件/保护固定；几何检查需要 URDF |
| 手动比较动作速度 | 枚举 1×、2×，按预计时长选离线候选 | 有限枚举，不是学习；没有验证真实抓取成功率 |
| 经验缺少适用范围 | `rsi/memory.py`：显式审核，按 robot / setup / task 精确选取 | 只生成规划参考；审核身份是操作者声明，不是认证签名 |
| 复盘难以查看 | 本机独立 HTML：故障、假设、指标、候选、指纹 | 执行后生成，无实时控制或模型调用 |

## 更值得验证的研究方向

**研究假设：在整段粗计划驱动的真实操作中，少量失败证据能否形成带适用条件、可验证的局部轨迹修订，并在固定大模型调用预算下提升新场景成功率？**

目前这是待验证假设，不是已经成立的新颖性或性能结论。与 Zetta 的区别需要落到实验：修订对象是粗计划中的局部几何参数/关键点，基础执行器保持固定，关注稀疏真实经验和整段执行的调用预算。

下一阶段按顺序做：

1. **抓取参数接口。** 把接近、抓取、抬升、放置关键点关联到 TCP 目标和物体标识，通过 IK 重建局部路径；当前只有关节路径，不能把改某个关节直接称为“抓深若干毫米”。
2. **候选生成与验证分离。** GPT 或小模型只产出版本化 JSON 修订，验证器检查范围、连续性、动态和几何；先回放与仿真，再现场试验。本轮已有候选文件边界，尚无自动模型提案服务。
3. **冻结经验的留出评测。** 开发阶段修订，评测阶段冻结经验；对新物体姿态和摆放测泛化，避免把调参后的最后一次成功当作平均表现。

## 最小实验设计

| 条件 | 经验处理 | 保持一致的量 |
| --- | --- | --- |
| A 基线 | 无跨轮记忆 | 模型、任务、复位协议、控制器、调用预算 |
| B 文本经验 | 人工复盘文字进入上下文 | 与 A 相同 |
| C 结构化经验 | 带来源、适用范围和离线检查的修订 | 与 A 相同；候选次数与验证成本单独记录 |

开发集与留出集按场景划分；冻结 C 的经验再运行留出集。记录物体级/整任务成功、所有尝试和干预、保护停止、总墙钟时间、模型调用/费用、候选拒绝率；报告原始分母和不确定性。改变深度与方向时做独立消融。硬件/传输故障单独标注并公布处理规则，不静默剔除。

数值通过只说明已检查的约束成立。接触、滑落、物体是否入筐需要额外观测，最终结论必须来自新实验。
