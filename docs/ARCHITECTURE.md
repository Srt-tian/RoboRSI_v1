## 分层与接口

| 层 | 输入 | 输出 | 当前实现位置 |
| --- | --- | --- | --- |
| L1 RSI 跨轮改进 | 实验指标、基线/候选计划、明确审核与范围 | 证据、比较报告、审核经验、规划上下文 | `rsi/` 离线工具；[命令与接口](RSI.md) |
| L2 任务规划 | 新场景、任务、初始状态、人工选用的经验 | 关节关键点与夹爪事件组成的粗计划 | 交互式 GPT 会话 + `ik.py` |
| L3 轨迹编译 | 审核后的粗计划、URDF、动态限值 | 固定目标流、事件索引与校验信息 | `compiler.py` / `smoothing.py` / `geometry.py` |
| L4 执行与反馈 | 目标流与现场配置 | 命令、实测反馈、完成/异常状态 | `runtime.py` / `hold.py` / `reporting.py` |

**L1 是跨轮工作流，L2–L4 构成本轮任务链。** 向下传递的是经验、粗计划与目标流；向上回传的是执行证据与任务结果。L1 的修订经人工审核后才可被下一轮 L2 选用，不直接写正在执行的队列。

四层是职责与数据边界，不表示已经存在四个独立服务：L1 有离线命令行和本机工作台，修订采用仍需明确审核；L2 仍为交互式规划，L3、L4 提供编译与执行代码。经验记录不是模型参数，审核修订不等于自动训练。

规划者决定任务策略，IK 工具负责把候选末端位姿转成可达关节配置。最终交给编译器的是关节关键点，而非未经求解的 TCP 目标。仓库不含自动图像定位流水线或独立 GPT API 服务；不能把图中“规划”理解为运行编译命令就会自动调用模型。

## 两份计划文件，一组执行证据

```text
粗计划 program.json
  ├─ initial_state.q14
  ├─ trajectory.joint_waypoints（左臂 Nx6，包含起点）
  └─ gripper（目标开度 + 检查区间）
          ↓ roborsi-compile
目标流 stream.json
  ├─ targets（Nx14，200 Hz）
  ├─ events（阶段 / 夹爪检查）
  ├─ estimated_duration_s / 动态限值
  └─ 场景意图、URDF/代码指纹、几何检查标志
          ↓ 显式硬件执行
事件日志 + commands.jsonl + feedback.jsonl
          ↓ 执行后
本机 Web / 结果图像 / 人工任务确认
```

- 统一单位为米、真实弧度、秒；SDK 单位转换只在硬件边界进行。
- `q14 = [left_j1…left_j6, left_gripper, right_j1…right_j6, right_gripper]`。
- 连续阶段首尾必须一致。示例中右臂保持初始状态，不是双臂协作规划。
- 夹爪事件与关节插值分开，各保留 0.8 s 驻留，不随运动倍速机械缩短。
- 无 URDF 编译只完成数值与轨迹检查；`geometry_verified=false`，不能因此进入真机执行。
- 历史示例保留 `requires_fresh_scene_and_seed=true`，不能靠修改标签将旧场景计划变成新计划。

## 三种频率与两类闭环

| 对象 | 时序 | 作用 |
| --- | --- | --- |
| GPT 粗规划 | 执行前 | 固定本轮任务程序；最终记录中执行期间无新视觉调用 |
| 目标写线程 | 200 Hz，目标周期 5 ms | 按计划下发；主机频率不等于固件伺服频率 |
| 反馈监督 | 约 50 Hz | 检查跟踪误差、TCP 高度、夹爪和执行健康度 |
| RSI 修订 | 两轮实验之间 | 人工审核后修改下一轮计划 |

任务层在最终实验中视觉开环；设备保有自己的关节反馈控制。软件监督读取反馈用于保护、检查和结束收敛判断，不会基于视觉自动修正抓取位置。夹爪非零宽度可能来自空夹以外的接触，也不能证明物体已放入篮筐。

## 平滑、时间缩放与下发各做什么

`smoothing.retime` 使用 PCHIP 形成 C1 连续关节轨迹，检查分段多项式的速度和加速度极值，并拉长时间以满足限制。编译器随后检查完整离散目标流。这里不提供 jerk 连续性保证，也不以更密的采样点代替动态约束。

`--speed 2` 的运动速度上限是 1× 档位的两倍，加速度上限是四倍；夹爪驻留保持不变，因此不能把整轮耗时简单除以二。连续轨迹的时间缩放与 200 Hz 写线程是独立职责：前者定义动作时间，后者决定命令发送节拍。

当前任务执行固定目标流，不产生滚动的新预测 chunk，因此不需要将 temporal ensemble 作为主流程模块。若后续引入执行中策略更新，必须新增时间对齐、过期结果处理与状态一致性设计，不能仅将新点追加到现有队列。

## 跨轮 RSI

独立的 [RSI 机制文档](RSI.md) 给出证据 D、候选验证 V、审核经验 E 与规划上下文 C 的命令和字段约定。`rsi/` 复用编译器离线检查，不调用执行器。

图中的虚线表示人工监督的跨轮反馈，不表示实时视觉伺服或在线自动训练：

1. `analyze` 保留已有指标及指纹，区分执行完成、结果报告和未知结果。
2. 错误文本按规则分型；定位、姿态、深度等保留为待验证假设。
3. `evaluate` 对受限候选重编译；`sweep` 枚举既有 1× / 2× 时间配置。
4. `review` 保存明确审核；`context` 仅选取适用范围匹配且被采用的记录。
5. 下一轮读取新场景与状态，重新规划、编译与检查，不自动从停止处恢复。

历史修订的例子是抓浅后增加深度、改变夹爪方向、纠正物理左右臂映射。这些是可追溯经验，尚不是训练得到的改进策略，也没有严格统计对照来证明某一项修改的独立贡献。

## 图中的模块对应哪些代码

| 模块 | 源码 | 需要注意的边界 |
| --- | --- | --- |
| RSI 离线迭代 | [rsi/](../src/roborsi/rsi/) | 指标分型、候选重编译和已审核经验选择；不自动推断物理成功或执行动作 |
| 运动学工具 | [ik.py](../src/roborsi/ik.py) | 规划阶段使用；编译器只使用 FK 做几何验证，不自动调用 solve 生成路径 |
| 几何检查 | [geometry.py](../src/roborsi/geometry.py) | 当前双臂基座偏移和距离阈值；不是完整环境网格碰撞检测 |
| 插值与重定时 | [smoothing.py](../src/roborsi/smoothing.py) | 连续关节路径及动态边界 |
| 编译 | [compiler.py](../src/roborsi/compiler.py) | 生成目标流、事件与可追踪元数据 |
| 执行与验证 | [runtime.py](../src/roborsi/runtime.py)、[validation.py](../src/roborsi/validation.py) | 单写者、队列补充、状态/时限/夹爪监督 |
| 保持 | [hold.py](../src/roborsi/hold.py) | 新鲜状态与线程退出是前提，不伪造保持目标 |
| 本地反馈查看 | [reporting.py](../src/roborsi/reporting.py) | 只播放实测反馈；没有自动任务判定或实时模型调用 |

## 如何扩展

更换模型需要新增规划服务适配及输出验证；更换机械臂需要重审 action 布局、URDF、几何假设和设备控制接口。新增视觉闭环或小 VLM 要单独验证触发条件、动作时间对齐、延迟、取消和保护，不直接复用本轮成功作为新模块已有效的证据。

当前版本的真实实验记录和离线重构验证分别陈述，见[实验记录](EXPERIMENTS.md)与[证据边界](PROVENANCE.md)。
