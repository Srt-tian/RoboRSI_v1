# RoboTwin 原生专家资格验证：任务完成，进程退出异常

本记录属于基础设施开发，不是 JEV / RSI 学习结果，也不是统计意义上的基准成功率。
固定 RoboTwin 提交 `13c3c47ff4312dd62484bcd51be034af55c062d1`，
采集工具提交 `dc5eff88104728c21269afd626108dab0d9b79e2`。
采用 demo_clean、Aloha AgileX、原生专家、250 Hz 物理步进和 5 Hz 执行时渲染。
任务和种子在执行前指定；未因失败重新抽取种子。

| 任务 | 种子 | 仿真任务判定 | 物理步 | 仿真秒数 | 视频帧 | 进程情况 |
|---|---:|---|---:|---:|---:|---|
| handover_block | 0 | 成功 | 3,778 | 15.112 | 76 | SSH 命令返回 255；未单独捕获子进程状态 |
| lift_pot | 0 | 成功 | 1,532 | 6.128 | 31 | 父进程捕获子进程 -11，即 SIGSEGV |

结果、视频、逐物理步记录均在异常退出前完成保存。逐步记录行数和视频索引数量已核对。
保留任务成功判定，同时将进程稳定性标为未通过；不能将非零退出码改写成成功。
抬锅实验由父进程保存退出码与完整日志，从而排除仅靠 SSH 退出码判断的歧义。

独立 Python 3.11 环境使用 SAPIEN 3.0.0b1、Mplib 0.2.1、Toppra 0.6.3、
Open3D 0.18.0、NumPy 1.26.4、Torch 2.7.1 + CUDA 12.8。
CuRobo 五个 CUDA 扩展已 JIT 编译，实际 GPU 算子和渲染已验证，pip check 通过。
Torch 版本与 RoboTwin 当前安装脚本中的 2.4.1 不同，尚未验证其对广泛任务的影响。
旧 Python 3.10 环境拷贝缺失 Torch 共享库，因此未用于这些回合。

下一步先定位 SAPIEN/CUDA 资源销毁和 Python 退出阶段的错误，使用明确的清理顺序验证修复，
保留失败日志。不能用强制 os._exit、忽略信号或把任务成功当作退出成功来绕过问题。
稳定性恢复后再按预登记任务与种子扩展；所有学习方法对照仍需新的冻结协议。
